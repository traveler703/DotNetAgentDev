# 10 分钟演示与答辩准备

## 一、演示时间安排

### 0:00 - 1:00 项目背景

讲解要点：

- 旅行规划同时受路线、预算、住宿、交通、天气和政策约束。
- 普通聊天模型容易一次性生成内容，缺少事实工具和约束复核。
- 本项目使用主控 Agent 协调五个专业 Agent。

### 1:00 - 2:00 架构说明

打开 `docs/架构设计.md` 的总体架构图。

讲解要点：

- LLM 是决策组件，不直接执行 C# 函数。
- Agent Loop 负责反复调用模型、执行工具、加入 Observation。
- Tool Registry 是模型与业务工具之间的安全边界。
- Memory 分为当前任务工作记忆和 JSON 长期记忆。

### 2:00 - 3:30 输入旅行需求

使用首页“填入示例”：

```text
上海 → 日本
7 天，1 人，12000 元
喜欢美食、城市漫步、人文和夜景
轻松节奏，不想太赶
```

指出右上角当前是 DeepSeek 还是离线模式，并解释两种模式共享相同 Agent Loop。

### 3:30 - 5:30 展示结果

依次展示：

1. 方案总览：城市数、活动数、工具调用数。
2. 每日行程：东京、京都、大阪的日期与节奏。
3. 预算交通：费用明细和超预算调整。
4. 风险提醒：天气、签证、安全和模拟数据声明。

强调预算 Agent 使用的是其他 Agent 返回的实际估算，而不是预设比例。

### 5:30 - 7:00 展示 Agent 轨迹

打开“Agent 轨迹”页签。

讲解：

- `Thought` 是系统级决策摘要。
- `Action` 展示工具名称和参数。
- `Observation` 展示工具结构化返回。
- `FinalAnswer` 是专业 Agent 的子任务结论。
- 页面不暴露模型私有思维链。

### 7:00 - 8:00 展示长期记忆

打开“历史方案”：

- 计划按用户保存。
- 用户偏好被聚合。
- 新计划可以读取历史偏好，但当前输入优先级更高。

### 8:00 - 9:00 展示代码

重点打开：

1. `Agents/AgentLoop.cs`：有界 ReAct 循环。
2. `Llm/DeepSeekLlmClient.cs`：HTTP 与 tool calls。
3. `Tools/ToolRegistry.cs`：工具注册和异常边界。
4. `Agents/TravelCoordinatorAgent.cs`：并行专业 Agent + 串行预算 Agent。

### 9:00 - 10:00 总结

- 完成课程全部核心要求。

- 当前使用本地数据保证演示稳定。
- 可扩展到真实 API、数据库、RAG 和 SSE。

## 二、高频答辩问题

### 1. ReAct 是什么？

ReAct 是 Reasoning + Acting。模型先分析当前状态，再请求调用工具；程序执行工具后把 Observation 返回模型，模型继续判断，直到输出最终答案或达到最大步数。

### 2. Agent 和普通聊天有什么区别？

普通聊天通常一次调用模型生成文本。Agent 有持续状态、循环控制、工具执行和停止条件，可以根据工具结果多步完成任务。

### 3. 为什么不用 Semantic Kernel？

课程重点要求理解核心循环，因此直接使用 HTTP 和自定义循环，能明确解释每条消息和每次工具调用。未来可以把 LLM 或插件层换成 Semantic Kernel，领域模型不需要重写。

### 4. 为什么使用 async/await？

LLM、文件和工具调用都可能等待 I/O。`await` 在等待期间释放线程，使 ASP.NET Core 能处理其他请求，也支持取消令牌。

### 5. 如何防止 Agent 无限循环？

`AgentOptions.MaxSteps` 提供最大步数；工具有白名单；达到上限后保留已有 Observation，并返回明确状态。

### 6. 模型能调用任意方法吗？

不能。模型只看到当前 Agent 的工具 JSON Schema，执行时还必须通过 `ToolRegistry` 查找已注册名称。

### 7. 工具调用失败怎么办？

`ToolRegistry` 捕获异常，记录日志，并将错误包装为失败 Observation。Agent 可以继续判断；DeepSeek 本身失败则自动切换离线客户端。

### 8. Memory 如何实现？

短期记忆是当前 Agent 的消息列表、Observation 与主控共享上下文。长期记忆是 `App_Data` 下的计划 JSON 和用户档案 JSON。

### 9. 为什么最终计划不是完全由 LLM 输出 JSON？

模型 JSON 可能缺字段或格式漂移。系统让 LLM 做工具决策，让 C# 强类型代码负责日期、预算和最终格式，稳定性更高。

### 10. 离线模式算不算 Agent？

它不具备真正的 LLM 推理能力，但仍执行相同的 Agent Loop、函数调用和 Observation 流程，是演示降级方案。配置 API Key 后，工具选择由 DeepSeek 完成。

### 11. 如何证明是多 Agent？

每个专业 Agent 有独立职责、Prompt 和工具白名单，分别执行自己的 Agent Loop。主控 Agent 负责依赖关系和结果整合，轨迹页可看到每个 Agent 的调用。

### 12. 数据是否实时？

不是。景点、酒店价格、天气与政策为本地模拟参考，页面和风险工具都明确提示二次核验。真实 API 是后续扩展方向。

### 13. AI 在开发中做了什么？

Codex 辅助完成需求分析、架构、代码、测试、文档和验收。团队需要如实说明新增内容主要由 AI 生成初稿，成员负责理解、测试、修改和最终责任。

## 三、现场故障预案

| 故障 | 处理方式 |
| --- | --- |
| DeepSeek 无响应 | 系统自动降级离线模式，继续完整演示 |
| API Key 无额度 | 删除/取消环境变量，重新启动离线模式 |
| 现场网络中断 | 本地知识库和静态资源均可离线运行 |
| 历史数据异常 | 删除 `DotNetAgentDev/App_Data` 后重启 |
| 端口冲突 | `dotnet run --project DotNetAgentDev/DotNetAgentDev.csproj --urls http://localhost:5187` |
| 老师要求看测试 | 执行 `dotnet test` |
